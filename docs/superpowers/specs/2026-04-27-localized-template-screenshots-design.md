# Localized template screenshots

## Problem

The template gallery (`/templates`) and the event-creation template picker (`/dashboard/events/new`) show JPG previews generated by `server/db/templates-screenshots.ts`. The script is hardcoded to render every template in English (`EN_LOCALE_PATH = 'i18n/lang/en.json'`) using English-flavored sample data ("Saturday, June 14th, 2026", "The Grand Ballroom"). When the user switches the site to Spanish, the surrounding UI translates but the screenshots remain English, which looks broken to a Spanish-speaking visitor.

We want a parallel set of Spanish screenshots and a way for the frontend to pick the right one based on the active i18n locale.

## Goals

- Render every template in every supported locale (`en`, `es`) so the previews match the language the user is browsing in.
- Localize both the translated tokens (e.g. `{{t:templates.and}}` → "y", `viewOnMap` → "Ver en el mapa") and the sample data (couple names, date string, venue, wording).
- Wire the consumer pages to the locale-correct preview URL automatically when the locale changes.
- Avoid a database migration or API change — keep the surface thin.

## Non-goals

- Adding new locales beyond `en` and `es` (the design accommodates more, but this work ships only the existing two).
- Removing the now-unused `previewImageUrl` DB column — that's a separate cleanup if we ever do it.
- Server-side locale negotiation for the preview URL — locale resolution stays on the client where the user's selection lives.

## Architecture

Two orthogonal pieces:

**Build-time.** `server/db/templates-screenshots.ts` loops over a fixed list of locales. For each locale it loads the corresponding `i18n/lang/<locale>.json`, extracts a new `templates.sampleData` block as the substitution data, renders every template HTML, and writes the JPG to `public/images/templates/<locale>/<slug>.jpg`. Skip-if-exists logic operates per `(locale, slug)` pair, so a re-run after a partial failure only generates what's missing.

**Runtime.** A small composable `useTemplatePreviewUrl()` reads the active locale from `useI18n()` and returns `/images/templates/${locale}/${template.slug}.jpg` for any template. The two consumer pages call it instead of dereferencing `template.previewImageUrl`. The DB column is left in place and still populated during seed; it is simply ignored by these two consumers.

## Locale file changes

Add a `templates.sampleData` block to `i18n/lang/en.json` and `i18n/lang/es.json`. The keys mirror the fields of `TemplateData` in `server/utils/template-substitute.ts`:

```jsonc
// en.json — under the existing "templates" object
"sampleData": {
  "coupleName1": "Maria",
  "coupleName2": "James",
  "date": "Saturday, June 14th, 2026",
  "venue": "The Grand Ballroom",
  "venueAddress": "123 Wedding Lane, City",
  "wording": "Together with their families, they invite you to celebrate\ntheir marriage."
}
```

```jsonc
// es.json — under the existing "templates" object
"sampleData": {
  "coupleName1": "María",
  "coupleName2": "Jaime",
  "date": "sábado, 14 de junio de 2026",
  "venue": "El Gran Salón",
  "venueAddress": "Calle de la Boda 123, Ciudad",
  "wording": "Junto a sus familias, les invitan a celebrar\nsu matrimonio."
}
```

These keys are read only by the screenshot script — no UI surface consumes them. They will, however, be in the runtime locale bundle the browser downloads. The size cost (~6 short strings × 2 locales) is judged acceptable in exchange for keeping all locale-keyed copy in one place.

## Screenshot generator changes

`server/db/templates-screenshots.ts`:

- Replace `EN_LOCALE_PATH` and the hardcoded `SAMPLE_DATA` constant with a `LOCALES = ['en', 'es'] as const` list.
- For each locale: load `i18n/lang/<locale>.json`, validate that `templates.sampleData` exists with all six required fields (fail loudly if any are missing — prevents silent renders with `undefined` text), and ensure `public/images/templates/<locale>/` exists.
- For each template slug under that locale: skip if `public/images/templates/<locale>/<slug>.jpg` already exists, otherwise render `template.html` with `substituteTemplate(html, sampleData, translations)` and write the JPG.
- Reuse a single Puppeteer browser instance across the entire run (existing behavior). Close pages per render.

`substituteTemplate` itself does not need changes — it already accepts arbitrary `TemplateData` plus a translations object and resolves both kinds of placeholders correctly.

## Initial migration

The 6 existing top-level files at `public/images/templates/*.jpg` are deleted as a one-shot `git rm` step before the first run of the updated script. This guarantees the EN and ES sets are produced by the same renderer version (same fonts loaded, same crop logic) rather than mixing fresh ES screenshots with possibly-stale EN screenshots from an older renderer.

After deletion, running `npm run templates:screenshots` produces 12 files: `public/images/templates/{en,es}/<slug>.jpg` for each of the 6 templates.

## Frontend composable

New file `composables/useTemplatePreviewUrl.ts`:

```ts
export function useTemplatePreviewUrl() {
  const { locale } = useI18n()
  return (template: { slug: string }) =>
    `/images/templates/${locale.value}/${template.slug}.jpg`
}
```

The composable returns a function (not a computed) so a single call site in a `v-for` can build URLs for many templates. The locale ref is reactive, so a locale switch triggers Vue to re-evaluate the function inside `:src` bindings and the new URL is requested automatically.

## Consumer changes

`pages/templates/index.vue`:

- Add `slug: string` to the local `Template` interface.
- Inside `<script setup>`: `const previewUrl = useTemplatePreviewUrl()`.
- In the `<img>` block, replace `:src="template.previewImageUrl"` with `:src="previewUrl(template)"`.
- Simplify the `v-if` guard from `template.previewImageUrl && !brokenImages.has(template.id)` to `!brokenImages.has(template.id)` — the URL is always derived now, and the existing `@error="onImageError(...)"` handler still falls back to the gradient placeholder if the file is missing for any reason.

`pages/dashboard/events/new.vue`:

- Import and instantiate the same composable.
- The two `<img>` blocks (around lines 446–448 and 477–479) use `previewUrl(tpl)`.
- `tpl` already includes `slug` from the API response and is currently typed as `any` (`recommendedTemplates = ref<any[]>([])`), so no type change is needed at the call site.

The DB `previewImageUrl` column, the `/api/templates` endpoint, and `server/db/load-templates.ts` are all left untouched. No migration, no API contract change, no test changes.

## Testing

Manual verification only. There is no new logic that warrants a unit test — the URL builder is one line, and the existing `substituteTemplate` tests already cover token resolution.

Manual checklist:

- Run `npm run templates:screenshots`. Confirm 12 files exist under `public/images/templates/{en,es}/`.
- Spot-check one EN and one ES screenshot. EN should read e.g. "Maria and James", "Together with their families…". ES should read "María y Jaime", "Junto a sus familias…", with localized "and"/"y" and date.
- `npm run dev`. Visit `/templates` in EN, confirm previews load. Switch the site to ES, confirm the same grid now shows the Spanish-text screenshots without any broken-image fallbacks.
- Visit `/dashboard/events/new` and repeat the same EN/ES check on both `<img>` blocks (collapsed list and expanded selection states).
- Run `npm test` to confirm the existing template/load tests still pass.

## Trade-offs and alternatives considered

- **DB-stored per-locale URL map** (`previewImageUrls: Record<Locale, string>`). Rejected — requires a migration, an API shape change, and updates to ~5 test fixtures, in exchange for no functional benefit over a deterministic client-side path.
- **Server-side locale negotiation** of the preview URL based on the request locale. Rejected — couples the API to the user's locale and complicates SSR/caching for a path that's already deterministic given a slug + locale.
- **Sample data in a separate config file** rather than the i18n bundle. Considered cleaner (build-time concern doesn't pollute the runtime bundle), but rejected in favor of consolidating all locale-keyed strings in `i18n/lang/*.json` for a single source of truth.
- **Locale suffix in filename** (`<slug>.en.jpg`) instead of a subfolder. Equivalent functionally; subfolder chosen for clarity (`ls public/images/templates/es/` shows the full Spanish set at a glance).
